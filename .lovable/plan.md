# Facebook authentication review

## Findings

### 1. Form field missing id/name (fixable)
Several form controls in `/admin/facebook` are missing `id` or `name` attributes, so the browser cannot autofill them correctly. The specific fields are:

- The *Import all Pages* checkbox
- The *Let Maggie answer Messenger automatically* global checkbox
- The *Maggie may auto-reply here* per-thread checkbox
- The Messenger reply textarea
- The new post textarea
- The optional link input
- The comment reply inputs
- The schedule-publish datetime input (has aria-label but no id/name)

These warnings are generated by our own admin page, not by Facebook.

### 2. Unload event listener deprecation (not fixable from our code)
The warning `Unload event listeners are deprecated and will be removed. 1 source 5lm6wGmyFDH.js:288` comes from `5lm6wGmyFDH.js`, which is a Meta/Facebook CDN script. The warning does not originate in the Magnolia Maids codebase, so we cannot remove it. We can only suppress the warning if we stop loading the Facebook SDK or switch to a newer Meta embed script. There is no current Facebook SDK load in the app source, so the script is likely injected when the OAuth popup or the embedded Meta preview is active.

## Plan

1. Add unique `id` and `name` attributes to all form controls in `src/routes/_authenticated/admin/facebook.tsx`.
2. Where appropriate, link checkbox labels with `htmlFor` and checkbox inputs with matching `id` so the label is clickable and accessible.
3. Add `id` and `name` to the Messenger reply textarea and the comment reply inputs.
4. Add `id`/`name` to the post composer textarea, link input, and datetime-local input.
5. Verify the page still compiles and the warnings disappear from the browser console for this source file.
6. Document that the `unload` deprecation warning is from Meta's third-party script and cannot be removed from our side.
